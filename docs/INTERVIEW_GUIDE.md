# 三分钟面试演示指南

## 第 1 分钟：讲业务问题

打开首页，说明跨境电商运营每天要检查 Listing 完整度、FBA 库存和订单时效。指出页面上的低库存和超时订单指标，以及 SP-API 当前处于样例数据或只读授权模式。

## 第 2 分钟：跑自动化

点击“运行完整 Demo”。展示四个步骤：数据校验、运营分析、Playwright 填写草稿、报告生成。打开 RPA 截图，说明脚本使用稳定的元素定位和显式等待，操作完成后才取证。

再运行“演示失败与恢复”，第一次在浏览器步骤失败，然后点击重试。展示尝试历史，并解释为什么已经成功的数据校验与分析不会重复执行。

## 第 3 分钟：讲真实接入与工程边界

打开 `/api/integrations/amazon/status` 和 `/docs`。说明项目采用 `python-amazon-sp-api`，配置 LWA 凭证后可读取 FBA 库存和订单状态；当前没有卖家账号，所以使用相同字段结构做契约测试，不伪造生产调用。

最后展示 SQLite、JSON/Markdown 报告和测试结果，说明 AI 是可替换分析层，即使模型服务失败，默认规则模式仍可复现演示。

## 常见追问

**为什么不用 Selenium？**  
Playwright 自带自动等待、现代浏览器上下文和更直接的截图/追踪能力，适合这类需要稳定取证的 RPA 流程。

**为什么不直接复制一个完整 GitHub 项目？**  
成熟 SDK 负责 Amazon 鉴权和 HTTP 细节；数据映射、运营规则、任务编排、RPA、审计与测试由本项目实现，个人贡献更清楚。

**没有真实卖家账号，SP-API 怎么证明？**  
证明分为三层：SDK 可以安装和加载；缺凭证时零网络保护；官方响应字段的契约测试通过。真实授权联调明确列为下一阶段。

**如果上生产还要做什么？**  
完成卖家授权、按接口角色申请权限、处理分页和限流、增加任务队列与告警，并为任何写操作增加人工审批和回滚策略。
